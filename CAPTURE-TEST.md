# Capture test

## 1. Tool and model

- **Tool:** Claude Code (VS Code extension)
- **Model:** Claude Opus 5.5 (`claude-opus-5-5`). The same model plans and executes; there is no separate planner model.
- **Hook mechanism:** yes. Claude Code has lifecycle hooks; `UserPromptSubmit` fires on every prompt and `Stop` fires at the end of every turn.

## 2. Mechanism and config

- **Config changed:** [`.claude/settings.json`](.claude/settings.json) (committed in the repo)
  - `UserPromptSubmit` → `node .claude/hooks/capture.mjs prompt`
  - `Stop` → `node .claude/hooks/capture.mjs response`
- **Script:** [`.claude/hooks/capture.mjs`](.claude/hooks/capture.mjs)
  - **Prompt:** taken verbatim from the hook's `prompt` field.
  - **Final response:** the assistant text after the last tool call of the turn, read from the session transcript (`transcript_path`), with `last_assistant_message` as a fallback. Thinking, tool calls and intermediate text are not logged.
  - **Timestamp:** UTC, taken when the hook fires.
  - **Model:** read from the latest assistant message in the transcript.
  - One file per session: `.agent-logs/YYYY-MM-DD_HH-MM-SS_<session-id>.md`. Entries are append-only; only the front-matter counts and times are rebuilt from the entries after each write.
  - Errors are written to a temp file outside the repo and never block the agent.

## 5. What did not work first

- **The docs lookup was wrong about a field name.** A helper agent reading the Claude Code docs said the prompt arrives as `user_prompt`. The raw hook input showed it is `prompt`. The script reads both.
- **My first simulated test failed.** I passed hand-written JSON through zsh `echo`, which turned `\n` into a real newline, so the input was invalid JSON. The script logged the error and exited cleanly as designed. I reran the test with JSON generated by Node.
- **A log file was created before any prompt.** The `Stop` hook of the turn that installed the hooks created the session-1 file with a header and no entries, so its filename time (12:10:30) was earlier than the first prompt (12:16:34). Fix: only a prompt can create a session log. I renamed that one file to its first prompt time before anything was committed; no entries were changed.
- **No headless second session.** The `claude` CLI is not installed on this machine, so the second session was a new chat in the VS Code extension.

## Known limitation

- **The first prompt of a new session logs `model: unknown`.** The transcript has no assistant message yet, and the prompt hook input has no model field. The response entry that follows records the model (see session 2). Entries are not edited after the fact.
